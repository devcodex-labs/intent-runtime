# V1 实施基线（2026-10-09）

以用户提供的最新技术方案为准。既有 0.1.0 原型不约束目标 V1，也不维护旧原型导出。仓库和 scoped npm 包身份保留为 @devcodex-labs/intent-runtime。

- 唯一解析入口为 parse({ input, fields, context })；省略 fields 提取全部，[] 只取消扩展，默认结果完整。
- 默认 en。接受登记有效且能指定输出语言的 BCP 47 标签；拒绝 und、mul、zxx、纯私有及仅保留私有码标签。配置合法性与语言效果分开记录。
- 缺省 $schema 按 Draft-7；显式其他方言拒绝。unsupported 关键字和运行时函数不静默删除。
- 可选字段无依据时省略，必填字段无依据时反馈；null 必须既被定义允许，又有材料明确表达为空的依据。
- 候选格式、类型、来源、选择范围和有依据字段的遗漏进入最多一次修复。真实缺失、歧义、冲突、容量或真实值无法表达不逼模型猜值。
- 所有候选接收和修复分类由同一核心状态机实现，parse 与 bridge 共用。data 失败保留已校验默认结果，data 不部分提交。
- 内部 fieldResults 覆盖所选顶层字段，用于检查遗漏与反馈一致性；不增加公共结果字段。模型自评与来源存在不证明语义正确。
- 候选深度/节点、证据与问题数量、桥接重放数量/字节均有上限；不静默截断业务结果。

真实模型与桌面客户端由用户在本地手动验证；自动化合同测试、模拟 SDK/MCP 往返不冒充真实联调。真实语义场景结果只有实际运行后才能记录为通过。

实施锁定依赖版本见 package-lock.json。IANA 子标签数据来自完整性校验的 language-subtag-registry 0.4.2，File-Date 2025-08-25；当前机器无法读取 IANA 官网，未声称其为最新登记数据。扩展 singleton 基线为 RFC 6067 的 u 和 RFC 6497 的 t；扩展内容按 BCP 47 语法保留，不解释为业务指令。维护时通过 registry:refresh 显式更新官网快照，不在运行时联网。
