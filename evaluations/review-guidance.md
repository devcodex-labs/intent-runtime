# 语义结果复核

semantics.jsonl 将需求附录 D 的 S-01—S-81 转成具体原始输入和语义检查要求，保留编号；展开变体共 89 条。languages.jsonl 包含六种语言材料，总计 95 条评测输入。云端当前会话助手已逐条执行并自评，证据见 [完整报告](../docs/cloud-test-report-2026-10-09.md)；独立评审和真实 OpenAI/xAI/桌面路径验收仍未完成。

复查已发现 S-22/S-70 分类错误，三例待裁决；不要沿用原始自评全通过作为准确率。additional.jsonl 增加 24 条明确检查维度的材料，作者、生成者和自评者重合，且包含原输入复测，不是独立留出集。后续事实以 [复查报告](../docs/coverage-accuracy-review-2026-10-09.md) 和 correction 记录为准。

先运行单例，再运行完整场景。evaluate 保存实际材料、定义、结果/错误、模型、阶段调用数与耗时，所有语义判定初始化为 pending；exit 0 不代表语义评测通过。

逐例对照原始 input、显式 context 和 Schema，检查：有效动作有无遗漏/新增、对象和方向、多对象对应、否定/例外、数值单位、全局/局部要求、先后与全部前提、确认范围、已完成历史、未知/澄清、说明语言、精确值、扩展来源和完整性。fields 全部/部分/[] 只允许改变 data 范围与扩展反馈，默认语义应一致。

记录每个语义点 pass/fail、理由及引用的原始片段，不逐字比对措辞与 id。格式合法、引用命中或模型自报 satisfied 不证明语义正确。可用独立 AI 辅助评审；有分歧时人工裁决。失败后保留原例和 Prompt 版本，修复后重新运行受影响用例及关键回归。

真实准确率需要先冻结完整标注，再由目标模型生成、独立评审；未裁决样本单列，输入拒绝不混入识别分母。分别报告完整请求语义通过率、各动作 precision/recall、状态与条件正确率、字段值及来源完整率、一次成功率/修复率。按模型、语言、Prompt 摘要和运输路径分组，重复请求单独衡量稳定性；保留修复前错误，不只评分最终合法 JSON。新增领域和自然输入另作留出集，不能用已看过答案的助手自评建立生产准确率。

候选发布门槛：确定性合同全通过；81 组在 OpenAI、xAI 与目标桌面路径分别留证；关键授权、否定、确认、续接、精确值、多对象及扩展失败场景每路径重复至少五次，样本内无已知关键违规。普通场景通过率目标 ≥95%，按路径列出分母和未运行项。该目标不是当前准确率，有限样本不提供零失误保证。

桌面路径需要按 integrations/codex/workflow.md 逐例交接给当前模型，并保存实际工具往返。此 Node runner 只驱动 API，不能把它计入桌面验证。性能预算在真实基线取得后锁定，记录修复率、p50/p95 与费用；当前 120 秒只是上限。
