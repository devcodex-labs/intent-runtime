# 项目定位

Intent Runtime 将用户意图结构化，供你的应用或 MCP tools 读取。它接收请求和你提供的相关材料，返回目标、要求、限制、业务参数及需要澄清的问题。

例如用户说“查询订单000123，不取消订单”：组件识别查询目标和禁止取消的约束；配置orderId字段后，还能保留字符串编号"000123"。应用读取这些结果，决定是否调用自己的订单系统。Intent Runtime本身不会查询或取消订单。

| 你提供 | 你得到 |
|---|---|
| 原始 input | 当前用户表达的目标与约束 |
| 自由 JSON Context 或可选 baseline | 有材料依据的关联、补充、修改与撤回 |
| 可选业务 Schema 和 fields | 归属明确的参数、验证状态及问题 |
| 可选语义定义 | 按你的领域术语解释动作和对象 |

不配置 Schema 也能识别意图；字段提取是按需启用的能力。结果的理解、参数校验与业务授权是不同层次，见[结果消费](/guide/results)。

如果用户只说“分析这个项目”，也可以识别分析目标；没有提供项目材料时，它不会读取仓库、补出项目能力或自动拟定实施步骤。若指代不清，会保留待澄清问题。

先按[接入选择](/integrations/index)找到你的入口，再按[快速开始](/guide/quick-start)运行一个调用，最后用[结果读取指南](/guide/results)理解返回值。所有参数和完整类型集中在API参考中，无需入门时全部读完。

它只理解调用方提供的材料。结果中的目标和先后关系来自用户表达；它不搜索项目或历史、不选择业务工具、不生成实施计划、不管理业务任务、不授权或执行操作。模型调用和本地校验是识别依赖。

应用拥有消息、模型来源、最终结果和业务状态。多轮调用显式传入相关 Context 或上次 `effective`。模型候选经过来源、业务规则、身份和公共结构检查；程序检查不等于自然语言正确率。

V2 API 与结果版本为两种标识：npm 包报告其 package version；成功结果和 baseline 的 `schemaVersion` 固定为 `2.0-draft.6`。
