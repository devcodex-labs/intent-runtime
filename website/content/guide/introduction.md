# 介绍

intent-runtime 是面向开发者与 AI 客户端的大模型意图结构化组件，使用 TypeScript / Node.js 实现。它把调用方提供的当前用户请求与显式上下文，表达为统一的意图记录，并根据 JSON Schema 或 schema-dsl 定义提取所选业务字段。

它适合需要把自然语言交给业务应用处理的场景：理解用户要做什么、对象是谁、有哪些要求与禁止事项、哪些动作需要澄清或确认，以及材料中能确定哪些业务字段。

## 在应用中的位置

语义理解由接入的大模型完成。模块提供识别指令、公共契约、候选校验与识别流程管理；最终结果交给上层应用使用。

```text
当前 input + 可选 context → 模型生成候选 → 模块校验与组装 → IntentResult → 应用处理
```

适用场景包括自然语言业务入口、AI 客户端的结构化识别，以及上层应用进行澄清、路由或规划前的意图输入。工具选择、任务规划、业务授权和实际执行由应用实现。

例如“分析这个项目”，模块识别分析意图、对象与用户表达的约束。仅凭这个目标，当前实现不会补出“读取代码、运行测试、分析依赖”等实施步骤，也不会输出所需能力或工具清单。用户明确提出多个动作时，会保留这些动作及其顺序和前提；这与推断一个完成目标的计划不同。

## 接入方式与模型来源

| 路径 | 候选由谁生成 | 需要的配置 |
| --- | --- | --- |
| Codex MCP | 当前 Codex 会话中的模型 | 命名 instance、MCP 注册、识别 Skill；无需模型 API key |
| 应用调用 | 执行器接入的模型 | 内置 API 适配器显式配置 provider、model、apiKey；也可提供自定义 ModelExecutor |
| 独立 stdio MCP | 宿主模型 | 本地依赖、可信配置、标准客户端启动生产 CLI |
| 已有 MCP host Adapter | 宿主模型 | 在原工具列表注册三个协作工具，绑定逻辑 session |
| 已有 MCP executor Adapter | 服务器 executor | 在原工具列表注册 intent_parse，明确模型与业务实例 |

各接入路径共享同一套公共结果与本地校验逻辑。应用 parse 或 MCP executor 模式使用显式配置的执行器完成识别，内置 API 适配器支持 OpenAI 与 xAI。MCP host 模式由宿主重复执行 `prepare → accept`，直到结果或错误；注册工具后仍需明确启用识别流程。

已有 MCP 的 Adapter 为下一兼容版本新增接口；当前源码支持，npm 1.0.2 保留 SDK/Bridge/独立 stdio。它复用同一流水线，不要求宿主更换 SDK 或复制核心逻辑，见[嵌入已有 MCP](../integrations/existing-mcp.md)。HTTP 监听由外部宿主提供，本轮不增加 CLI HTTP 参数。

## 两阶段流程

1. **core：默认意图。** 识别当前有效请求，生成归一化表达、主要意图、动作列表、要求与禁止事项。
2. **data：业务字段。** 存在所选扩展字段时，根据 Schema 和明确材料提取字段，检查类型、描述、来源和问题。`fields: []` 跳过该阶段。

候选 JSON、结构或来源引用不符合输出契约时，会产生 `MODEL_OUTPUT_INVALID`；候选完整、请求未取消且仍有修复次数时，模块会要求模型修复候选。默认每阶段允许一次修复。

材料中的真实业务信息缺失、冲突或业务约束不满足会产生 `DATA_EXTRACTION_FAILED`，直接反馈问题，不通过候选修复猜测补齐。鉴权、限流、取消等错误也不会触发候选修复。

最终交付完整 `IntentResult`，或带阶段和问题说明的错误。data 阶段失败可保留已经验证的默认结果，部分结果中的 `data` 为 `{}`。

## 输入与职责

调用方提供原始 `input`，并选择是否补充显式 `context`。模块不会自行读取文件、加载完整聊天历史或发现业务工具。最终 `input` 保留模块收到的字符串；宿主提交前是否改写原文，需要在集成中验证。

省略 context 仍会识别当前 input；只有“它”“按刚才的来”等依赖前文的信息，才需要补充相关材料或澄清。模块没有自动收集上下文或跨请求记忆的机制，见[上下文与字段选择](../examples/context-fields.md)。

`ready` 是理解状态。业务权限、用户批准和实际动作执行由应用负责。使用该模块不会自动查询订单、删除文件或发布内容。

业务字段来源在 data 候选阶段校验，最终结果只返回公共 data，不包含完整证据链。来源匹配和结构校验能够发现部分错误，真实语义是否正确仍需目标模型评测与独立复核。

## 运行要求

包名为 `@devcodex/intent-runtime`，要求 Node.js **≥20.0.0**，使用 ESM；已发布版本见站点导航和发布记录。新增 Adapter/原生取消选项的适用版本在参考页单列，源码能力不等于 npm 1.0.2 已发布能力。
